# ONPRINT

ONPRINT is a full-stack platform for a professional printing-services business: a public marketing site, a customer portal for quotes/orders, and an admin panel — built for production deployment on traditional GoDaddy/cPanel hosting (no serverless platforms).

## Status

Phase 1 (project scaffolding) is complete. The public site routes, customer routes, and admin routes are wired up; the API exposes health checks, categories, products, and services. Features are being built phase-by-phase — see [Roadmap](#roadmap).

## Tech stack

- **Client:** React 19, Vite, React Router, Tailwind CSS, Axios
- **Server:** Node.js, Express
- **Auth:** JWT + bcrypt (added in Phase 4)

## Project structure

```
onprint/
├── package.json    Single production Node app: express, cors, helmet, morgan
├── server.js        Entry point — binds PORT immediately
├── src/              controllers/, routes/, middleware/, data/, app.js
├── client/           React + Vite frontend, its own package.json/toolchain (src/{components,pages,layouts,services,hooks,context,assets})
├── dist/             React production build (generated by `npm run build`; gitignored)
├── .env.example
└── README.md
```

There is one Node application, deployed as a single process (matches how cPanel's Node.js App manager works: one Application Root, one `package.json`, one startup file). In production, `server.js` serves `/api/*` from Express and everything else from the built React app in `dist/` — no separate frontend host is required. `client/` keeps its own `package.json` only because the Vite/React/Tailwind build toolchain shouldn't be a production dependency of the API.

```
GoDaddy Node.js Hosting
        │
        ▼
     server.js
        │
        ├── /api/*  → Express API
        └── everything else → dist/ (built React app)
```

## Local development

Requires Node.js 18+.

```bash
npm install
```

(`postinstall` automatically installs `client/`'s dependencies too.)

Copy the env templates and fill in real values:

```bash
cp .env.example .env
cp client/.env.example client/.env
```

Run the API and the Vite dev server together:

```bash
npm run dev:all
```

- Client (hot reload): http://localhost:5173
- API: http://localhost:5000/api (health check at `/api/health`)

Or run just the API with `npm run dev` (nodemon), or just the client with `npm run dev:client`.

## Environment variables

| File | Used by | Notes |
|---|---|---|
| `.env` (root) | Express API | `JWT_SECRET`, `PORT`, `CLIENT_URL`, `STORAGE_DRIVER`, etc. Never commit. |
| `client/.env` | Vite build | Only `VITE_`-prefixed vars are exposed to the browser bundle. |

## Production

```bash
npm install
npm run build   # builds client/ into dist/
npm start        # node server.js — one process, serves API + dist/
```

`server.js` reads `PORT` from the environment (falls back to `5000` only for local dev) and binds to `0.0.0.0` immediately.

## Deployment (GoDaddy / cPanel)

- Point cPanel's **Setup Node.js App** at this repo: Application Root = repo root, Startup File = `server.js`.
- Run its "Run NPM Install" (executes `npm install`, which also builds nothing by itself — run `npm run build` once, or as a deploy step, so `dist/` exists before first start).
- Set environment variables in the panel: `JWT_SECRET`, `CLIENT_URL`, `NODE_ENV=production`. `PORT` is provided by the panel automatically — do not set it yourself.
- Start the app. `/`, `/api/health`, and every other frontend route are all served by the same process/port.

No Vercel/Netlify/serverless-only APIs are used anywhere in this codebase.
